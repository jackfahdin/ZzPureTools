# 开关圆点主题配色实施计划

**目标：** 按用户确认的 FluentUIStyle 方向，让开启态圆点响应深浅主题，并保持任意强调色下的可辨识性。

**方案：** 浅色表面优先白色圆点，深色表面优先使用表面深灰色；与强调色的对比不足 3:1 时，先尝试同一明暗方向的黑白极值，再回退到对比更好的黑或白。悬停和按下的轨道混色以实际圆点前景为依据，保持圆点颜色稳定。关闭、禁用、高对比主题、动画数量和交互语义保持现有契约。使用已有线性亮度查表，绘制不新增对象分配。

**文件：** `ZzToggleSwitch.cpp` 负责配色装配；`ZzControlAppearancePrivate.h/.cpp` 复用亮度查表并提供对比计算及指定前景的状态填充；`ZzToggleSwitchTest.cpp` 检查真实渲染；受影响的 Linux 截图基线经审阅后更新。

- [x] 像素回归先红：同一个默认强调色切换深浅主题，圆点明暗改变；明亮和深暗自定义强调色、三种交互状态下实际对比至少 3:1。
- [x] 实现配色与前景感知的轨道填充，复验键盘、可点击区域和动画复用。
- [x] 重建 Debug Example，运行本机最小门禁与四档截图；只更新受影响场景，不修改阈值。
- [x] 独立审查后中文提交，记录实际验证及待验证平台；不推送。

## 验证记录

- Ubuntu 26.04.1 LTS、Qt 6.11.1、GCC 15.2.0、CMake 4.3.3，`linux-gcc-debug`。
- 本机最小门禁完整构建及 216 项普通 CTest 通过；定向正则 `^fluent\.(toggle-switch|button.*|standard-controls|calendar-controls)$` 的 4 项通过。
- 像素测试覆盖 10 种强调色 × 2 个主题 × 3 种状态，包含纯黑白及半透明颜色；主题切换和半透明临界颜色均先复现失败再修复。
- 对显式圆点前景禁止纯黑白轨道反向混色，避免半透明合成后对比降低；这些极值颜色仍使用圆点形变反馈。其他控件未指定前景时沿用原混色行为。
- 12 项四档截图 CTest 通过，关闭更新模式后复验；仅更新深色总览的 4 张基线，已查看 100% 和 200% 效果。
- 独立审查通过；Debug Example 已重建。既有 `docs/research/` 保留。
- 待验证：Windows、macOS、Qt 6.8、CI、ASan/UBSan、clang-tidy、专项性能与物理桌面交互；本机结果不替代远端发布门禁。
